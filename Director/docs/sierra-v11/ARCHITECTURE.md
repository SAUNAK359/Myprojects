# Sierra Vision v11 Production Architecture

This document is the current architecture authority for the Android application under `Director/`.
Older ANIP-era descriptions are historical and must not be interpreted as the active final-photo pipeline.

## Authority

```text
Device Foundation + verified device capabilities
                  ↓
             Gemini / Sierra
      photographic creative authority
                  ↓
       camera intent + DirectorSpec
             + RenderSpec
                  ↓
              Sierra β
  perception + feasibility + deterministic execution
                  ↓
          CameraX / Camera2
                  ↓
               hardware
```

Hard rules:

- Gemini decides the photograph when AI mode is available.
- Sierra β may quantize/clamp to real hardware/API values, reject impossible controls, measure reality and execute the plan; it does not invent a replacement artistic concept.
- Hardware limits win.
- Unknown measurement evidence is never success.
- Identity, geometry, readable text, materials, luminous-source hierarchy and intentional blacks are protected.
- OEM extensions are execution tools, not authorities.
- ANIP is not the active creative finishing authority in v11. The active final renderer is `SierraRenderExecutor` executing a validated `SierraRenderSpec`.

## Two-call Gemini lifecycle

```text
Call #1
  current analysis frame
  + Device Foundation
  + situation signature
  + recent creative memory
       ↓
  photographic concept
  camera controls
  Director strategy / goal graph
  FULL RenderSpec
       ↓
β physical feasibility / camera execution
       ↓
requested → resolved → applied → actual verification
       ↓
Live Director local loop
       ↓
pre-shutter target converges OR deterministic no-progress constraint
       ↓
Call #2 — SECOND AND FINAL Gemini call
  latest preview
  + original intent
  + camera telemetry
  + goal measurements
       ↓
PASS or ONE bounded correction
       ↓
local execution + local verification
       ↓
fresh readiness check
       ↓
FINAL SHUTTER
       ↓
JPEG / P-RIF
       ↓
cached Call #1 RenderSpec
       ↓
SierraRenderExecutor
       ↓
technical safety / MediaStore
```

There is no post-capture Gemini creative call and no third Gemini correction loop.

## Director schema v2

`director.v2` is generated by `DirectorSchemaCompiler` from verified on-device model availability.

The spec contains:

- strategy: portrait, candid, group, fashion, food, product, architecture, landscape, night or general
- intervention policy: observe, minimal, directed or high-direction
- exact primary-entity current/target boxes
- typed goal graph
- tolerances and confidence floors
- dependencies / invalidations
- stability requirements
- readiness policy

Only locally measurable goal types are exposed.

Current physical goals include:

- primary entity placement and scale
- visibility
- subject luminance
- left/right light balance
- subject-to-background image-space EV separation
- background distraction score
- motion stability
- technical sharpness
- relative-depth separation when the verified depth expert exists
- pose alignment when the verified pose expert exists
- face placement when the verified face expert exists

### Candid protection

For `CANDID + OBSERVE/MINIMAL`:

- pose may not be capture-blocking
- subject reposition may not be a hard requirement
- local coaching prioritizes photographer movement, framing, timing, exposure and motion safety

This is validated locally even if Gemini emits an invalid graph.

## Situation signature

`SierraSituationSignature` replaces reliance on a single coarse scene label. It exposes independent measured dimensions such as:

- human presence/count/coverage
- low light
- bright sky
- scene structure
- dynamic range
- flatness
- subject separation/depth confidence
- frame orientation

Gemini consumes this evidence; Sierra β can use the same evidence for local planning.

## Rendering

AI mode:

```text
Gemini Call #1 → validated SierraRenderSpec → SierraRenderExecutor
```

Beta mode:

```text
measured TechnicalQuality + SceneSignals + SituationSignature
       ↓
SierraBetaRenderPlanner
       ↓
SierraRenderSpec
       ↓
SierraRenderExecutor
```

Installed themes are optional descriptive priors only. They are not a creative gate and an unknown/custom/blank theme does not invalidate an otherwise valid RenderSpec.

Legacy named-look injection was removed from the active β final path.

## Memory model

The production ownership target is:

```text
captured evidence file
      +
at most one decoded full-size source
      +
at most one mutable output surface when source protection is required
      +
bounded scanline/tile pixel buffer
```

Important safeguards:

- crop occurs before expensive final rendering in the active file path
- `SierraRenderExecutor` uses a bounded tile buffer instead of a full-frame `IntArray`
- P-RIF protects reconstruction evidence when the renderer would otherwise mutate it
- before/after comparison uses a cache-only ~1280px JPEG, never a second retained full-resolution photograph
- Gemini image requests stream JPEG → Base64 directly into OkHttp instead of materializing JPEG bytes + Base64 String + full JSON String at once

## Network / cancellation

Per-shot Gemini streaming is asynchronous and coroutine-cancellable:

```text
coroutine cancellation → OkHttp Call.cancel() → socket terminates
```

The total stream does not use an arbitrary wall-clock response deadline. Connection/write/read timeouts and the socket read timeout remain the transport/stall safeguards.

The one-time Device Foundation setup is a small non-image request and is not in the per-shot image upload path.

## Observability

Each shot emits real `PipelineEvent` objects. The UI and persisted audit consume the same event stream.

Actors include:

- Gemini
- Sierra β
- Camera
- Live Director
- Capture Engine
- P-RIF
- Render Executor
- Technical Gate
- Storage

The UI never fabricates percentage completion for post-capture work. It displays only real stages/events.

Execution receipts expose:

```text
requested → resolved → applied → actual
```

with `APPLIED`, `CLAMPED`, `REJECTED` or `FAILED` state.

## Completion / comparison

A successful MediaStore URI is the terminal save signal. The completion surface provides:

- explicit “Saved to Gallery” state
- final photo preview
- Open / Share
- before-Sierra-render vs Sierra-final comparison when a render was executed

The comparison reference is a bounded cache artifact and is not a hidden second full-resolution original.

## Per-shot audit

`ShotAuditStore` writes bounded app-private JSON records containing observable execution evidence only:

- mode / scene / objective
- provider / latency / fallback
- execution receipts
- actual camera state summary
- readiness state
- timeline events
- final render/save result and URI

Hidden Gemini reasoning is never persisted.

## Failure behavior

- AI unavailable before planning → Sierra β is shown explicitly; no claim of Gemini direction.
- invalid Gemini schema → reject before execution.
- impossible camera value → quantize/clamp to closest physical value where mathematically meaningful, then verify actual state.
- unresolved camera failure → fail the AI preparation rather than pretending it executed.
- Live Director no-progress → Call #2 may move the target once to the closest achievable version of the same concept.
- final correction fails → no Gemini #3; shot does not become prepared.
- final render unavailable/unsafe → preserve captured evidence instead of inventing a local AI style.
- catastrophic finishing failure after evidence exists → preserve untouched safety capture where available.

## Release truth boundary

A successful hosted compile/unit/lint/APK workflow verifies source/build/package integrity. It does **not** by itself prove physical Camera2/CameraX/OEM behavior. Real-device qualification is tracked separately in `DEVICE_QUALIFICATION.md`.
